# Устройство прототипа

Nginx обслуживает единую точку входа на 6752. Next.js отвечает за рабочий кабинет, FastAPI - за данные и действия. PostgreSQL хранит материалы, неизменные исходные записи, версии выпусков, задания, evidence, результаты модели и журнал. Миграции Alembic выполняются до старта приложения.

Worker берёт задачу с row lock из PostgreSQL. Lease/heartbeat позволяет восстановить зависшую задачу. Advisory lock оставляет один активный worker для прототипа; отдельный advisory lock сериализует обращения к модели между процессами API и worker. Идемпотентные ключи защищают импорт, расписание, создание задач и тестовую отправку от повторов.

Материалы проходят валидацию даты и полноты, семантическую классификацию и извлечение через GigaChat. Каждое утверждение связывается с точным фрагментом исходного текста. Допускается нормализация пробельных символов, но сохраняется реальный фрагмент и его offsets. Неподтверждённые утверждения исключаются после ограниченного исправления ответа.

Группировка объединяет кандидатов в события и сохраняет все ссылки. Отбор использует последствия, масштаб, срочность и задачи аудитории. Указаны оценки и подтверждающие claim_id. Масштаб может быть неизвестен. До пяти событий, без заполнения пустых мест вымышленными новостями.

Для выпуска используется единый объект событий. Пост сокращается выбором предложений полного текста, ссылки остаются теми же. Статусные оговорки и расхождения из подтверждённых claims добавляются в оба формата. Подсчёт знаков исключает только зарегистрированные URL и одинаково считает Unicode code points в Python и TypeScript.

Незавершённые этапы сохраняются в checkpoint. Возобновление использует сохранённые факты и стадии, если совпадают snapshot, контрольное время, параметры и fingerprint кода/промптов. Изменение контекста аннулирует кеш. Ручная группировка создаёт новый запуск и оставляет родительский результат в истории.

Промпты и их hashes, фактический model identifier, usage и длительность сохраняются. Ошибочные прогоны не удаляются. ZIP включает текст, письмо, пост, журнал, evidence, snapshots промптов и результаты проверок отдельно для live-модели и fixtures.

## Защита

- Session cookie HTTP-only, пароль Argon2, CSRF и роли.
- Secrets только через runtime env, в браузер не выдаются.
- Модель не имеет инструментов сети, shell, рассылки и изменения конфигурации.
- Crawler получает только разрешённые URL и проверяет DNS, IP, порт и redirects. Соединение идёт с проверенным IP, TLS использует исходный hostname.
- Robots, ограничения частоты/размера/таймаутов, без обхода доступа.
- HTML письма экранируется; данные новости не исполняются.
- ZIP не извлекается в произвольные пути, CSV защищён от формул.
- SMTP только для allowlist. Автоотправка выключена по умолчанию; при явном включении остаётся ограниченной утверждёнными выпусками и тестовыми адресатами.

## Ограничения

Смысловой verifier использует ту же модель с другой задачей. Это дополнительная проверка, а не независимое подтверждение фактов. Публикация может быть ошибочной сама по себе. Редакторская проверка необходима. Адаптеры и правила времени могут требовать обновления при изменении сайтов.

Пользовательский интерфейс не включает полноценное управление учётными записями и историей всех конфигурационных версий. Для прототипа предусмотрены bootstrap admin и локальный read-only просмотр. Изменение сложных адаптеров выполняется через config/sources.json; начальные пять RSS настроены.

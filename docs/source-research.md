Проверка завершена **2026-10-14T18:39:17Z** по UTC, полученному инструментом часов. Проверены реальные HTTP-ответы официальных сайтов через Python requests и XML через стандартный XML-парсер; HTML — через BeautifulSoup. Это исследование возможности адаптеров, не сбор для выпуска и не редакторское согласование.

В [config/sources.json](../config/sources.json) сохранены все **28 адресов из реестра кейса**. Для всех источников `enabled=false`, `agreed=false`. Поле `url` сохраняет адрес из кейса; `candidate_section_url` показывает проверенную предложенную область сбора и не считается автоматически согласованным разделом.

## SecurityMedia: HTML работает, рекламируемый RSS сломан

Официальная главная страница объявляет `https://securitymedia.org/rss/` через alternate link. Проверка вернула HTTP 200 и `application/rss+xml`, но тело начинается с:

```text
Cannot find 'rss' template with page ''
```

Остальная выдача — HTML cookie-блока; XML-парсер сообщает `junk after document element`. Следовательно, проверять и статус, и фактическую структуру содержимого. В конфигурации рабочий `feed_url=null`, объявленная нерабочая ссылка хранится отдельно, статус `html_verified_feed_invalid`.

- HTML-раздел: [Новости информационной безопасности](https://securitymedia.org/news/).
- Карточки: `article a[href]`; дата карточки `time.date[datetime]`.
- Статья: [В России растет спрос на защиту ИИ](https://securitymedia.org/news/v-rossii-rastet-spros-na-zashchitu-ii-.html).
- Основной контейнер: `.education-content__wrapper`, 1835 символов.
- Дата `14.10.2026` только календарная. Хранить `date_precision=day`; **не присваивать придуманные часы**.
- Для строгого скользящего 24-часового интервала, если принадлежность дня периоду неоднозначна, исключать с `DATE_PRECISION_INSUFFICIENT` до проверки. Для календарного периода можно использовать известную точность только по явно выбранной политике выпуска.
- Source-specific HTML-адаптер должен быть отдельной явно настраиваемой альтернативой RSS, с лимитом числа страниц.

## Robots и частота

Проверены официальные robots.txt:

| Хост | Ограничения для общего User-agent |
| --- | --- |
| xakep.ru | `Crawl-delay: 30`; закрыты поиск, служебные `/wp-`, URL с UTM |
| habr.com | `Crawl-delay: 10`; закрыты поиск, некоторые страницы профилей, URL с UTM |
| www.securitylab.ru | Проверенные /news и RSS не закрыты; административные, поисковые, служебные пути закрыты |
| safe.cnews.ru и www.cnews.ru | Новостные статьи доступны; закрыты preview, print, поиск, redirect.php |
| securitymedia.org | /news и проверенная статья не закрыты; закрыты /bitrix, auth, /api, поиск и tracking query |
| 3dnews.ru | Общий доступ, закрыты preview и отдельные query patterns |

Значение 10 секунд у источников без объявленного Crawl-delay — консервативная **настройка прототипа**, не утверждение о наличии такой директивы в robots. Для Хакера и Хабра значение взято из robots. У каждого хоста отдельное ограничение частоты; запросы страниц одного хоста нельзя выполнять одновременно, если это нарушает интервал.

Robots необходимо повторно проверять на реальном запуске, кэшировать с ограниченным сроком и сверять после redirect. Недоступный robots или изменившийся запрет фиксировать отдельным состоянием, а не игнорировать. Доступность robots не равна лицензии на перепубликацию.

## Требования к внедрению

1. Не включать источники и не устанавливать согласование из seed. Предложенная область сбора должна быть видима редактору.
2. Реальная статья проходит SSRF, URL allowlist, redirect, robots, HTTP timeout, размер ответа, тип содержимого, извлечение, дату и фактологический контроль.
3. RSS description — возможный анонс, не гарантированный полный текст. При ошибке получения тела помечать материал неполным; не создавать «подтверждённый» полный пересказ.
4. Сохранять исходный URL, конечный URL, canonical, оригинальные даты, timezone, precision, источник каждой даты, обнаруженные конфликты, snapshot и версию адаптера.
5. Не заменять дату публикации временем загрузки и не подтверждать неизвестную дату по заголовку HTTP Last-Modified.
6. Дедупликация убирает известные tracking-параметры, но сохраняет параметры, определяющие материал.
7. Изменение HTML должно приводить к состоянию extraction_failed/needs_review, а не к извлечению меню или рекламы как тела новости.
8. Контент статей — недоверенные данные, а не инструкции для модели или приложения.
9. 22 непроверенных записи реестра не получают выдуманных feed, селекторов и времени проверки. Их `verification_status=not_verified`.
